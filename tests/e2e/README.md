# RustCut end-to-end suite

Drives the REAL desktop app (debug build with the embedded frontend) through its WebView2 over
the Chrome DevTools Protocol with `playwright-core`. Keyboard scenarios use real key presses
(PRD section 5); other scenarios use accessible controls or IPC for setup. The app is always started with an isolated data folder and works on COPIES of
the `rustcut-testkit` fixtures in a fresh temp folder, which is deleted afterwards.

## Run

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;" + $env:Path
$env:CARGO_TARGET_DIR = "D:/RustCut/target"
npm.cmd run e2e:build # tauri build --debug --no-bundle (a plain cargo build loads devUrl, not dist/)
npm.cmd run e2e       # node --test, one file after another (CDP port 9333 is shared)
```

Prerequisites: FFmpeg sidecars in `src-tauri/binaries` (`npm run sidecars`) and the fixtures in
`.fixtures` (generated by `rustcut-testkit`). `RUSTCUT_E2E`-style switches are not needed;
nothing is installed or left running: each test stops its app (graceful, then by PID) and the
harness only ever inspects FFmpeg processes whose command line contains its own temp folder, so
other FFmpeg jobs on the machine are never touched. Close any existing RustCut instance
before running: single-instance hand-off would otherwise target somebody else's window.
The original three-file suite took about 2.5 minutes; the expanded suite has not yet been timed.

## Isolation

* `RUSTCUT_DATA_DIR` (added to `src-tauri/src/lib.rs` for this suite) moves data, cache and logs
  under one folder, so the real `%APPDATA%\app.rustcut.desktop` is never read or written.
* `WEBVIEW2_USER_DATA_FOLDER` points at the temp folder; `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`
  opens `--remote-debugging-port=9333`.
* The video is opened by launching the app with its path (the real `get_launch_path` route).

Not covered here (covered by crate tests or needs a native dialog): AC-04 (1,000-kill loop),
AC-07/08 bit-identical and frame comparisons, AC-15 property test, and the native
file picker buttons (`Choose file...`, `Browse...`), which cannot be driven through CDP.
AC-14 and PRD §8.1 measurements have a separate opt-in script: `npm.cmd run perf -- --quick`
or a full release run. See [PERFORMANCE.md](../../docs/PERFORMANCE.md) for workloads,
targets, measurement limits and results templates. Never run it concurrently with this suite.

For a syntax-only check that launches no app, run `node --check` on each changed
`.mjs` file. `node --test`, `npm.cmd run e2e`, and the performance script without
`--help` launch the desktop app and belong in a later, exclusive verification step.

## Integration fixes made while writing the suite

| File | Fix | Why |
| :--- | :--- | :--- |
| `src-tauri/src/commands.rs` | `start_waveform` is now `async fn` | Sync commands run outside the Tokio runtime; the first call panicked ("no reactor running", media.rs:120) and, because the panic crossed the FFI boundary, aborted the whole app seconds after every video was opened. |
| `src-tauri/src/lib.rs` | `RUSTCUT_DATA_DIR` override for the data/cache/log folders | Isolated runs; Tauri resolves per-user folders with the Windows known-folder API, which ignores `APPDATA` overrides. |
| `package.json` / lockfile | `@tauri-apps/api` pinned to 2.11.x, `@tauri-apps/cli` 2.11.5 | `tauri build` refuses mismatched minor versions (crate `tauri` is 2.11.6, npm API was 2.12.4). Added `playwright-core`, `e2e` and `e2e:build` scripts. |

## Observations (not fixed, outside the minimal-fix scope)

* The first export after a fresh start waits for hardware-encoder probing (6 to 10 s on this
  machine, the dialog shows "Starting..."); later launches reuse `hw_encoders.json`. Lossless
  exports do not need it, so probing could be deferred for them.
* The legacy seek helper retries when relative seeks do not settle. The new keyboard
  regression deliberately sends two L presses without waiting between them and requires +10 s.
  The export suite also exercises Enter during pre-flight; current desktop results are pending.
* Zoom keys (`+`, `-`) work while the detail timeline has focus, not globally.
